# Non-shell payloads ride the command queue as an opaque `snippet` kind, not a typed target taxonomy

The command queue needs to carry things the user *pastes* but doesn't run in a shell — nvim keystrokes, SQL queries, file text bound for Word. We could have enumerated a target per destination (`nvim | sql | word | …`) with per-target syntax highlighting, but instead the entry's `kind` is just `bash | pwsh | snippet`: the two shells stay as before, and everything else is an opaque `snippet` the system never inspects, carrying an optional free-text `hint` (e.g. `psql query`) shown as a sub-label so a full queue stays unambiguous. We chose opacity over a taxonomy because the airgapped side is always a manual human paste — the system gains nothing from knowing nvim-vs-sql, the human already knows from the chat context and the hint, and a growing enum of targets plus highlighters is ongoing cost for a cosmetic payoff. The trade-off we accept: no syntax highlighting for snippets, and `snippet · <hint>` is the only machine-visible classification. `kind` is per-call but defaults to silence-means-shell, so ADR-0003 (shell flavor from config, minimal per-call surface) is preserved — `snippet` is an opt-in extension of the old `shell` override argument, never the default.
