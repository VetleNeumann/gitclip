# Shell flavor is an MCP-side config, not a per-call MCP argument

`send_command` could have required `shell: 'bash' | 'pwsh'` on every call, forcing Claude to remember the airgapped box's OS context every time. We instead read the flavor from a config sitting next to the session: `GITCLIP_SHELL` env var, with optional fallback file (parallel to how the session id is resolved). The MCP attaches it to every write; the browser uses it for the copy-button label and code-block class. Per-call override stays available as an optional argument for the rare case Claude legitimately wants to push the other flavor (cross-OS instructions, demos), but the common case is one user, one airgapped box, one shell — and that should be set-and-forget, like the session. This matches the principle already established by ADR-0002: the long-lived bits live in config, the per-call MCP surface stays minimal.
